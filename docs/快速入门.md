# FormuMind 快速入门（5 分钟上手）

本文用真实界面截图，带你在 5 分钟内跑通一次完整的配方研发闭环。
完整功能说明见 [使用指南.md](./使用指南.md)（English: [QUICKSTART.md](./QUICKSTART.md)）。

---

## 准备：启动平台

```bash
# 一键安装（推荐）
./scripts/install.sh
cp .env.example .env    # 内网：FORMUMIND_API_AUTH_ENABLED=false

# 或手动启动
# 后端（终端 1）
cd backend
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
uvicorn app.main:app --reload --reload-exclude .venv  # http://localhost:8000/docs

# 前端（终端 2）
cd frontend
npm install
npm run dev                        # http://localhost:5173
```

打开浏览器访问 **http://localhost:5173**。无需大模型 API 密钥时平台完全离线可用；若服务器开启平台鉴权，请先在设置页填写 **API 访问令牌**（与 `FORMUMIND_API_TOKEN` 一致），或关闭 `FORMUMIND_API_AUTH_ENABLED`。

### 或用 Docker 启动

```bash
cp .env.example .env
docker compose up -d --build       # redis + backend + worker + frontend
docker compose exec backend alembic upgrade head   # 已有数据库升到最新
curl -s localhost:8000/health
```

**先看 `/health`**，它是唯一能告诉你「平台到底能不能干活」的地方：

```json
{"status":"ok",
 "database":  {"ok":true,"scheme":"sqlite"},
 "task_broker":{"required":true,"reachable":true},
 "datalab":   {"required":false,"reachable":false}}
```

`task_broker.reachable:false` 表示 Redis 不可达，此时**所有异步功能都会被拒绝**——研究、推荐、逆向设计、寻优。处理办法见文末[故障排查](#故障排查)。

> **选定一种 compose 启动方式后就不要再换。** `docker compose up` 走桥接网络；`-f docker-compose.yml -f docker-compose.host.yml` 走 host 网络。中途切换只会重建部分服务，其余留在旧网络里——典型症状是 redis 显示 "Up"，但 `task_broker.reachable` 是 `false`。用 `docker compose down && docker compose up -d` 可以把所有容器强制对齐。

## 第 0 步 · 界面总览

FormuMind 采用仿 NotebookLM 的三栏布局，将**输入 → 研究 → 输出**分离：左栏是**资料来源**，中栏是**研究**问答，右栏是**操作**工具栏。标题栏含 **⚙ 设置**（大模型供应商）与 **🕐 历史**。

![总览](./images/01-overview.png)

- **左栏（资料来源）**：研究主题提示词框、来源类型复选框（专利 / 文献 / 互联网 / 本地文件 / **📓 NotebookLM**）——每个来源类型按钮旁有**状态指示点**（🟢 绿 = 在线可用、🟡 黄 = 离线种子回退、🔴 红 = 未安装对应库）——文件上传、**开始检索**按钮（其下方另有 **🔬 深度研究** 按钮，触发多智能体 DeepResearchEngine 综合研究，生成带引用的研究报告）、已加载资料列表。勾选「文献」或「互联网」时，面板内会出现 **🧪 ChemCrow 化学增强检索**状态徽章，指示化学语义增强是否已启用；若检索失败，面板顶部会显示**红色错误横幅**提示具体原因。
- **中栏（研究）**：基于已加载资料的接地问答对话，附引用标注。
- **右栏（操作）**：十个按钮，各自弹出聚焦窗口：

  | | 按钮 | 作用 |
  |---|---|---|
  | 🧪 | 技术需求 | 产品域、基材与优化目标 |
  | ⭐ | 推荐配方 | AI 检索并推荐 Top-N 配方 |
  | 🎯 | **逆向设计** | 给定目标性能，反向搜索帕累托前沿上的配方 |
  | 🔁 | **材料替代** | 断供或降本时，查替代料及其预测性能偏离 |
  | 🔬 | DOE 设计 | 生成实验方案并导出记录表 |
  | 📋 | 实验台账 | 填报实际参数与实测值 |
  | 📄 | **检测报告** | 上传报告，提取带方法与规格限的计量项并绑定实验 |
  | 📈 | 寻优收敛 | 贝叶斯多目标闭环优化 |
  | ⚙️ | 工艺优化 | 固化/分散/膜厚等工艺参数 |
  | 🔄 | 自驱动闭环 | 数据→重训→寻优→下一批 DOE 一键迭代 |

  加粗的三项分别见下文第 5b、5c、6b 步。

## 第 1 步 · 加载资料

输入研究主题（如"低 VOC 水性防腐蚀涂料"），勾选要检索的来源类型（专利 / 文献 / 互联网 / **📓 NotebookLM**），点击**开始检索**。也可上传本地文件（PDF/DOCX/XLSX/PPTX/HTML/图片），经 markitdown 解析。

![检索与资料](./images/02-search.png)

所有勾选来源的结果会被合并、去重、按相关度排序，列于左栏（每条可删除）。离线时专利检索返回精选种子语料；文献 / 互联网检索需安装可选的 `intel` 依赖；NotebookLM 需安装 `notebooklm` extra 并一次性浏览器登录（见完整使用指南 §12）。

**v0.9 新增 · 来源状态与深度研究**

- **状态指示点**：每个来源类型按钮旁的彩色圆点实时反映可用性——🟢 绿 = 在线可用；🟡 黄 = 离线种子兜底（专利永远有种子语料，始终为黄或绿）；🔴 红 = 缺少对应 pip 包，需先安装再重启。
- **🧪 ChemCrow 徽章**：勾选「文献」或「互联网」时，左栏会出现 ChemCrow 化学增强检索状态徽章，显示当前化学语义增强是否已启用（安装 `intel` extra 后自动点亮）。
- **🔬 深度研究**：点击「开始检索」下方的 **🔬 深度研究** 按钮，平台将调用 `/api/research/deep` 异步端点，运行 **DeepResearchEngine** 多智能体管线——`web_agent` 广域网络检索 + `kb_agent`（HyDE + 重排）知识库检索 + `report_agent`（强制引用）报告综合——最终生成带严格引用标注的综合研究报告，并自动推送至中栏展示。

## 第 3 步 · 选择大模型（设置）

点击标题栏 **⚙ 设置**。对话框含三个 Tab：

| Tab | 说明 |
|-----|------|
| **大模型** | 九家供应商（Claude、OpenAI、Gemini、Grok、Groq、DeepSeek、Qwen、Kimi、MiniMax）的模型与 **LLM API Key** |
| **API 配置** | Tavily、SerpAPI、EPO 等检索与数据源密钥 |
| **依赖管理** | 查看 / 一键安装可选 pip 包（`llm`、`intel`、`science`…） |

若顶部出现 **API 访问令牌** 横幅：这是平台 Bearer 鉴权（`FORMUMIND_API_TOKEN`），**不是**大模型 Key。内网可在 `.env` 设 `FORMUMIND_API_AUTH_ENABLED=false` 后重启后端。

选择供应商与模型、粘贴 API Key、按需填写 base URL，点**保存并测试连接**。未配置 Key 时，全部功能仍通过离线规则引擎运行。

## 第 4 步 · 一句话描述项目（✨ 智能解析）

## 第 5 步 · 推荐配方 + IP 合规分析

打开右栏 **⭐ 推荐配方**，点击**检索专利并推荐配方**。Top-N 排行榜随即出现 —— 每个配方卡显示成分表与预测指标，包括自动算出的 `cost_cny_per_kg`（成本）、`voc_gpl`（VOC）、`sustainability_idx`（可持续性指数）、**PVC / CPVC**（颜料体积浓度与临界值）、**Tg (°C)** 和 **viscosity_relative**（Fox 与 Mooney 模型），以及安装 `color` extra 时的 **lab_L/a/b + ΔE₀₀**。

点击任一配方卡的 **🔍 IP 合规分析**：平台检索相关专利、给出新颖性评分（0–1）并罗列侵权风险标注与白空间提示。展开配方卡可见 **3D 分子视图面板**，列出待用 3Dmol.js 渲染的带 SMILES 组分。

![推荐配方 · 含分子视图](./images/05-recommend.png)

## 第 5b 步 · 逆向设计 —— 从目标出发，而不是从模板出发

**⭐ 推荐配方**回答的是「我该试什么」。**🎯 逆向设计**回答的是更难的那个问题：*"耐盐雾 ≥1000 h、VOC ≤250、成本 ≤40 元/kg —— 同时满足这三条的配方有哪些？它们之间各自牺牲了什么？"*

打开 **🎯 逆向设计**，把目标分成**硬约束**（必须满足）和**软目标**（参与权衡优化），然后运行搜索。

与「对模板按比例缩放」的本质区别在于：**成分本身也是变量**。搜索会按角色从材料库里选料，而不只是调整一份固定配方的百分比。所以帕累托前沿上返回的是**成分集真正不同的配方**——不同的固化剂、不同的防锈颜料、不同的载体——而不是同一份配方把旋钮拧了几下。

- **硬约束**通过约束支配（constraint-domination）保证：可行解永远优于不可行解，所以返回的结果要么满足全部硬约束，要么明确报告「找不到可行解」。
- **软目标**决定前沿形状。返回的每个候选都是非支配的——不存在另一个候选在所有目标上同时更优。
- `rejected_infeasible` 会告诉你有多少候选被淘汰，这是判断「约束是不是定得太紧」最直接的信号。

该功能异步执行（`POST /api/design/inverse`），进度经 SSE 推送。

## 第 5c 步 · 材料替代与断供扫描

打开 **🔁 材料替代**，选择配方和有风险的那个成分。返回的是一份排序后的替代品清单，**每一项都带着对每个指标的预测偏离量**——而不只是「这几个化学上相似」。

排序融合三路信号：

1. **结构相似** —— 可互换组精确命中最高分，其次是化学族，再次是 Hansen 溶解度距离 `Ra = √(4Δd² + Δp² + Δh²)`；安装 RDKit 后再叠加 Tanimoto 指纹相似度。
2. **预测性能偏离** —— 用替代料重建基因组并重新预测，输出每个指标的 Δ。
3. **文献证据** —— 知识图谱里的 `substitutes` 边，每条都带着它的出处和原句。

> **看 Δ 之前先看 `delta_confidence`。** 没有 RDKit 时，预测器区分同角色材料只能通过角色用量、胺/环氧当量比，以及价格和 VOC 的查表值。实测替换三种环氧固化剂：成本有区分度（13.2 / 17.8 / 20.2 元/kg），而 `salt_spray_hours` **三者完全相同，都是 867 h**——这是模型没有分辨力，不是「换料对性能无影响」的证据。报告会用 `delta_confidence: cost_only` 如实标注这一点；装上 `science` extra 后该字段才会提升。

**断供扫描**：把某材料标记为 `discontinued`（`POST /api/materials/availability`），然后 `GET /api/materials/supply-risk` 会列出所有受影响的配方，并附上替代建议。

## 第 6 步 · 生成 DOE 并回灌实测结果

打开 **🔬 DOE 设计**，选择设计类型（如**中心复合 CCD** 或 **🧠 AI 主动选点**），点击**生成 DOE**。得到一张实验记录表，每行一个实验，列出各因子的自然值 + 一列空白"实测"。🧠 主动学习的行以紫色高亮，是期望改善（EI）选出的最具信息量的实验点。

![DOE 设计](./images/06-doe.png)

两种回灌方式：

1. **手动**：在"实测"列直接填入实验室测得的指标值，点击 **③ 回灌实验结果并训练模型**。
2. **批量**：点**导出 CSV** 把表发给实验室 → 填好后点**导入 CSV** 上传。

当某指标累积样本 ≥ 4 时，平台自动训练数据驱动模型，模型质量仪表盘会显示 R² 半圆仪表 + RMSE，之后的推荐与寻优会切换为"经验 + 实测"混合预测。

## 第 6b 步 · 用检测报告代替手工录入

「从 PDF 里把数字敲进表格」通常就是实测数据断供的地方。打开 **📄 检测报告**，选择报告所属的实验，上传文件即可。

抽取器会把每一个计量项**拆成独立的一行**——指标、数值、**单位、检测方法、规格限**——而不是过去那种只有 `{指标: 数值}` 的扁平字典。一条耐盐雾数据现在会记住它来自 ASTM B117、规格限是 ≥1000 h，于是后来的读数才是**可比的**，而不只是一个数。

整个入库在**单个事务**里完成，按内容哈希去重，并且**先挂附件再写计量值**——顺序反了的话，中途失败会留下一批查不到出处的数值。

回读用 `GET /api/qc/experiments/{id}/measurements`。

> 向后兼容：`ExperimentRecord.measured` 仍然存在，读出来仍是同一个扁平字典，只是现在由计量行派生。所有既有的读取方都不需要改动。

## 第 7 步 · 运行寻优闭环

打开 **📈 寻优收敛**，点击**运行 DOE 寻优闭环**，启动贝叶斯多目标寻优（默认 24 次迭代）。**收敛折线图**绘制每次迭代的最优目标得分（best-so-far），悬停可看精确数值。排行榜更新为寻优后的 Top-5 配方，同时平衡耐盐雾、成本与可持续性。

## 第 8 步 · 工艺优化 + 自驱动闭环

- **⚙️ 工艺优化** —— 把制造工艺参数（固化温度/时间、分散转速、膜厚、浴温、pH 等）作为独立优化空间，配合 Arrhenius / 经验产出模型联调。寻优引擎与配方寻优共用，仅作用于*工艺*空间。
- **🔄 自驱动闭环** —— 一键串联**实测数据 → 重训模型 → 贝叶斯寻优 → 下一批主动学习 DOE**。弹窗显示各指标 R²/RMSE 卡（含 ↓ 趋势箭头）、收敛折线图，以及下一批 DOE（紫色 = AI 主动选点）。可一键导出下一批 DOE，循环持续。

![自驱动闭环 · 收敛图与下一批 DOE](./images/09-loop.png)

> 每次研究 / 推荐 / 寻优 / 回灌 / 闭环成功后，平台自动保存一份会话快照 —— 点击标题栏 **🕐 历史** 可查看并恢复最近 20 次会话（存于浏览器 localStorage）。

## 第 9 步 · 配方版本谱系

每个配方卡都可以保存为一个**版本**，版本之间构成谱系——一条可以回溯的父子链。任取两个版本，差异是**结构化**的（新增/移除/调整的成分，外加重命名），而不是一段文本；作者没写备注时会自动生成一行摘要：

> 移除 1 项（聚酰胺固化剂）；新增 1 项（异佛尔酮二胺）；调整 2 项（环氧树脂、二甲苯）

端点：`POST /api/formulations/versions` 保存，`GET /api/formulations/versions?name=` 按名称查谱系，`GET /api/formulations/versions/{from}/diff/{to}` 比对差异。

## 故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 某功能返回 **503** 且提到 Redis | 队列不可达；本次提交已被记录，没有丢失 | `docker compose ps` 检查并启动 redis 与 worker。已记录的任务会自动重新入队 |
| `/health` 显示 `task_broker.reachable:false`，但 redis 看着是 "Up" | 服务分处不同网络，通常源于混用 compose 文件 | `docker compose down && docker compose up -d` |
| `/health` 显示 `task_broker.required:false`，但你确实起了 worker | 界面上保存过的「任务同步执行」开关曾能压过部署配置 | 已修复：现在部署配置优先，并会记录被忽略的值。去设置页把该开关关掉即可彻底清除 |
| 镜像构建卡在 `apt-get` | 那一层现在是可选的，默认关闭 | `git pull`。只有确实需要镜像内编译器时才加 `--build-arg INSTALL_BUILD_TOOLCHAIN=true` |
| 镜像构建卡在 `npm ci` | lockfile 不完整 | `cd frontend && npm install --package-lock-only`，提交结果 |
| `alembic: No config file 'alembic.ini' found` | 镜像版本较旧 | `git pull` 后重新构建；`alembic.ini` 现已打进镜像 |

界面上出现一句**具体的**错误描述是正常的——API 返回的 JSON `detail` 会被原样展示。反过来，如果只看到光秃秃的 `path -> 502`，说明这个响应根本不是 API 发出来的，要去查反向代理和后端是否可达。

## 下一步

- 想自定义多目标权重、约束 `constraint_values`、手动/AI 修改配方、配置多大模型与检索 API、对接真实引擎？见 **[完整使用指南](./使用指南.md)**。

> 离线产出的性能数值为工程合理的筛选估算值，非实验室验证规格。通过 DOE 回灌真实数据，预测会越来越准。
