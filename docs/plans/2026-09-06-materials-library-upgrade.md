# 材料库升级实施计划（2026-09-06）

## 目标

把材料库做成**组织级全局主数据**：可永久积累、跨项目共享、可批量进出，并持续供给替代 / 逆向设计 /（软偏好）推荐配方。

## 产品决策（已确认）

| 决策 | 选择 | 说明 |
|------|------|------|
| 库作用域 | **全局唯一** | 不建项目私有材料库；项目差异用收藏/置顶，不复制整库 |
| 推荐配方与材料库关系 | **仅「优先材料库」** | **不做「仅材料库」选项**；禁止把材料库变成硬约束候选池 |
| 自动扩充策略 | **半自动为主** | 高置信（CAS/SMILES/lookup 命中）可自动入库；仅商品名进待确认队列 |
| 写入契约 | **统一 upsert** | 手工、导入、KB 晋升、需求/配方回写共用同一去重与校验内核 |

### 推荐配方软偏好定义（强制）

- UI / API 仅增加开关：`prefer_materials_catalog`（文案：**优先材料库**）。
- **明确不做**：`materials_only` / 「仅材料库」/ 强制过滤非库内组分。
- 开启后行为（软偏好，非硬约束）：
  1. 仍走现有 KB + LLM 推荐主路径；
  2. grounding / 排序对**已命中全局库**的组分加权；
  3. 可在证据或提示中偏好库内常用料与供应状态更好的料；
  4. **不得**因「不在材料库」而丢弃、拒绝或阻断某条推荐配方；
  5. 可选：对未入库组分提供「一键入库」回写，但不影响本次推荐结果合法性。

## 分期实施

### Phase A — 批量导入 / 导出（P0，约 1 周）

**为何优先：**立刻可运营；并为自动扩充提供同一写入内核。

**后端**

- `POST /api/materials/import`
  - 格式：`json` / `csv` / `xlsx`（`xls`：尽量兼容读取，失败则提示另存为 xlsx）
  - 模式：`dry_run` → 预览新增 / 更新 / 冲突；`commit` 落库
  - 去重键优先级：`cas_no` > `smiles` > `norm_key(name)`
  - `origin=import`，记录批次 id（可先放扩展元数据）
- `GET /api/materials/export?format=json|csv|xlsx`
  - 支持 `q` / `role` / `availability` 过滤
- `GET /api/materials/import-template`（csv/xlsx 空模板）

**前端 `MaterialsPanel`**

- 「导入」「导出」入口 + dry-run 冲突预览表
- 明确格式说明与 xls 降级提示

**验收**

- ≥100 行 CSV 往返一致；重复导入幂等
- 新导入材料立即可被替代 / 逆向候选池读到

---

### Phase B — 自动扩充流水线（P0，约 1–2 周）

**统一晋升流水线：**候选 → 规范化 → 去重 → upsert → 刷新 `RAW_MATERIALS`

| 来源 | 触发 | 默认行为 |
|------|------|----------|
| KB / `kb_products` | ingest 完成或定时 job | 有 CAS/SMILES/lookup 命中 → 自动 upsert（`origin=kb_promoted`）；否则进待确认 |
| 技术需求 `Requirement.materials` | 保存需求 | 去重后晋升全局库 |
| 推荐 / 用户采纳配方组分 | 用户点「同步到材料库」或采纳时 | 解析后 upsert / 待确认 |
| 实验台账配方键 | 同步成功 | 未知键进待确认队列 |

**UI**

- 材料库增加「待入库」页签（一键晋升 / 忽略）
- 列表展示 `origin` 与来源摘要

**验收**

- 新项目文献 ingest 后库条数可增长且**跨项目可见**
- 进程重启后数据仍在；替代 / 逆向能用到新料
- 低置信名称**不会**静默污染主库

---

### Phase C — 推荐「优先材料库」软偏好（P1，约 0.5 周）

**范围（只做这些）**

1. 推荐请求增加布尔字段：`prefer_materials_catalog`（默认 `false`）。
2. 前端推荐面板增加开关文案：**优先材料库**（帮助文案写明：提高库内材料权重，**不会排除**库外材料）。
3. 后端在现有 grounding / 排序上对库内命中组分加权；可选在 prompt 侧加入「优先考虑供应状态良好的库内材料」软提示。
4. 推荐结果卡片：未入库组分显示「入库」快捷操作（不影响该条推荐是否合法）。

**明确不做（回归红线）**

- ❌ 「仅材料库」开关或等价 API
- ❌ 因不在库而过滤 / 拒绝推荐结果
- ❌ 把推荐主路径改成「从材料库枚举配方」

**验收**

- 开关关闭：行为与现网一致
- 开关打开：库内组分平均 grounding/排序更优，但故意构造的库外组分仍可出现在结果中
- API / UI 均不存在 `materials_only` 类参数

---

### Phase D — 硬化与体验（P2，随后）

- 软删除 / 归档（禁止物理删除 seed）
- `GET /api/materials` 补齐 `functional_class` / `substitute_group` 等文档已宣称过滤
- 导入审计日志；多用户后的写权限
- 导出列映射（对接客户 ERP）
- 替代 / 逆向默认可过滤 `discontinued`（可关）

---

## 不建议做

1. 每项目一份材料库（与全局化冲突）
2. 推荐「仅材料库」硬约束（已否决）
3. 无去重的全自动静默入库
4. 为材料库单独换存储引擎（沿用现有 SQLAlchemy 即可）

---

## 里程碑与依赖

```text
Phase A (导入导出) ──► Phase B (自动扩充) ──► Phase C (推荐软偏好)
                              │
                              └─► 替代 / 逆向自然受益
Phase D 可与 C 并行靠后
```

- A 不依赖 B/C，可独立上线。
- B 依赖 A 的 upsert/去重契约更稳，但技术上可并行起步。
- C **仅依赖全局库可读**；不依赖「仅材料库」任何设计。
- 替代 / 逆向无需单独大改，随 A/B 数据变大而增值。

---

## 成功标准（整包）

1. 任意项目写入或晋升的材料，其他项目材料库可见且进程重启仍在。
2. 支持 JSON/CSV/XLSX 批量导入导出（xls 兼容或明确降级）。
3. 替代、逆向持续使用同一全局库。
4. 推荐仅有「优先材料库」软偏好，**无硬约束选项**，且库外材料不会被剔除。
5. 自动扩充有溯源（`origin`）与待确认队列，主库不被噪声冲垮。
